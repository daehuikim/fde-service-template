# Baseline · 실제 관찰 대기

상태: human_validation_pending / service_validated=false

같은 합성 입력, 같은 권한, 같은 완료 조건으로 기존 스프레드시트와 후보를 비교한다. 사용자 숙련도를 기록하고 실행 순서는 가능한 경우 교차한다. 측정: 작업 성공률, 첫 유효 결과/전체 완료 시간, 수정/재입력 횟수, 오류 회복, 사용자 노력(1–5), 성공 작업당 비용.

| rubric | 통과 | 부분 충족 | 실패 |
|---|---|---|---|
| 작업 완료 | 개입 없이 export | 한 번 도움 필요 | 완료 못함 |
| 근거 이해 | 오류 원인/다음 행동 설명 | 일부 설명 | 오해 또는 설명 불가 |
| 오류 회복 | 입력 손실 없이 수정 | 재입력 일부 | 전체 손실/중복 저장 |
| 업무 적합성 | 용어/흐름 수용 | 우회 필요 | 업무 불가 |
| 전환 가치 | 관찰된 수고 감소 | 차이 불명확 | 더 많은 수고 |

관찰 기록: participant 가명, 날짜, baseline/candidate 순서, 사례 ID, 기대 결과, 실제 행동/인용, 시간, 개입, rubric, 개선안을 기록한다. 실제 관찰 전 점수는 비워 둔다. LLM 리뷰는 사전 검토로만 기록하고 사용성 연구와 구분한다. holdout split은 구현 중 반복 최적화에 사용하지 않는 운영 규칙이며 현재 초기 QA에서는 전 사례를 실행한다.
