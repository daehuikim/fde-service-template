# 인증·인가

코드: `examples/hackathon/hk/auth.py`, 테스트: `examples/hackathon/tests/test_auth.py`

## 인증(누구인가)

로그인하면 서버가 비밀번호 해시(scrypt)를 대조하고 서버 세션을 만든다. 브라우저에는 **세션 ID만** 쿠키로 준다(`HttpOnly; Secure; SameSite=Strict`). 서버 세션(`sessions` 표)에는 사용자 ID, 역할, 만료 시간을 둔다.

## 인가(무엇을 할 수 있나)

요청마다 서버에서 세 단계로 검사한다(`authorize()`).

| 단계 | 질문 | 예시 |
|---|---|---|
| 역할 | 어떤 종류의 사용자인가 | 조회자, 담당자, 팀장, 관리자 |
| 행위 | 이 API를 호출해도 되는가 | 담당자는 요청 생성, 팀장만 승인, 관리자만 예산 변경 (`ACTIONS` 표) |
| 데이터 범위 | 이 데이터가 자기 것인가 | 자기 라인의 요청만 조회·수정 |

- 요청한 사람은 자기 요청을 승인할 수 없다(코드 + DB CHECK `approved_by <> requested_by`).
- **401**은 누구인지 모를 때, **403**은 누구인지 알지만 허용되지 않을 때.
- 프론트의 버튼 숨김은 보안이 아니다. 검사는 항상 서버에서 한다.
- 목록 API는 범위 밖 데이터를 403이 아니라 **아예 빼고** 돌려준다. 단건 접근은 403.

## 테스트 4종

미로그인 401, 역할 불일치 403, 남의 데이터 403, 자기 요청 승인 403.

## 오늘은 제외(결정 기록에 남길 것)

TLS, 리버스 프록시, IP 제한, 비밀 저장소, 로그인 시도 제한, 감사 로그. "운영 시 필요, 오늘은 제외"로 `docs/DECISIONS.md`에 한 줄씩. 더 깊은 테넌트 격리·RLS는 `fde-enterprise-stack`과 `packages/auth`(Next.js 예제)를 본다.
