# Choose by the decision, not the technology

Ontology: shared meanings for concepts, relationships and constraints. Consider it for repeated cross-team semantic reuse; a graph database is a storage choice, not the definition of an ontology.

Harness: the execution surroundings for a model/tool workflow: context, state, permissions, budgets, cancellation, recovery, records and evaluations. A prompt or framework name alone is not a harness.

LLM provider: a managed or self-hosted inference endpoint. Separate the model's ability, service interface, operating burden, data location, latency and cost. Compare providers on the same task set only when an LLM is needed.

RAG: retrieve relevant source material and condition generation on it. It is not synonymous with a vector database and does not guarantee truthful answers, current policies or authorized access. Search without generation can be the right choice.

Rules and SQL: explicit validation, joins and bounded decisions. Compare them first when the inputs and policy are structured.

Optimization: choose among combinations under constraints and an agreed objective. Predictions and proxy scores do not establish a feasible or profitable plan.

Forecasting: estimate future or unobserved values. Requires representative data and a time-separated evaluation; do not invent confidence from a convenient dataset.

Workflow vs agent: predefined control flow vs model-directed next steps. Use autonomy only where path uncertainty warrants its extra cost and failure modes.

Scalability is a conditional decision: identify the bottleneck to measure, the signal to change methods, the new operating owner and the additional failure path. A list of queues, caches, models and databases is not an expansion argument.

Counterarguments matter: the existing spreadsheet may be sufficient; a missing dataset can be more important than a new model; an evidence-acquisition plan may be the right output instead of an investment recommendation.
